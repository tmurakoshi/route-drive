# ルート走行チェック（route-drive）

車で「事前に決めたルート」を忠実に回るための、スマホブラウザで動くWebアプリ（PWA）。
iPhone / Android 両対応。ビルド不要、HTML 1ファイル。

## できること
- GPX（rte / trk / wpt）または GeoJSON（LineString / MultiLineString / Point）のファイルからルートを読み込める。線の形を保ったまま最大 300 点に間引き、直線部分の中ほどを経由地にして道路に沿って引き直す（元の線とほぼ同じ道になり、ナビもそのまま使える）。読み込んだルートは経由地での U ターンを許可して計算するので、行き止まりの往復も再現される。このアプリが書き出した「計画」ファイルもそのまま戻せる
- 地図を順にタップして経由地を置くと、道路に沿ったルートを自動生成（OSRM）。経路の計算は「車（一方通行・進入禁止を守る）／自転車／徒歩（一方通行を無視して最短）」から選べる。車で意図しない回り道になる区間は一方通行か地図データ（OpenStreetMap）の問題
- 走行中は現在地を追従表示し、通った区間を緑、まだの区間を赤で塗り分け
- 走破率・走行済/未走行の距離・ルートまでの距離を表示
- 走行記録はスマホ内（IndexedDB）に保存。翌日「走行開始」で未走行区間だけ残した状態から再開
- このアプリ用の「ルートファイル」（`*.route.json`）を書き出し・読み込み。道路形状と右左折案内が入るので、読み込む端末では経路計算（通信）が要らない。「走行状況つき」は区間ごとの通過状況と GPS の生の軌跡（時刻・緯度経度・精度・速度）も入り、別の端末で続きから走れる。配布は作った人が 1 回だけ経路計算して書き出し、各端末はファイルを読み込むだけ
- GPX（計画ルート＋走行軌跡）/ CSV（15m区間ごとの通過有無）/ GeoJSON を書き出し
- 「計画／走行済／未走行」を 3 ファイルに分けて書き出し（GPX または GeoJSON）。iPhone は 3 つまとめて共有、まとめて共有できない端末は 1 ファイルずつ保存
  - GPX: 計画は `<rte>`、走行済・未走行は `<trk>`（連続区間ごとに `<trkseg>`）。Google Earth・Garmin・QGIS 等で読める
  - GeoJSON: 線ごとに `kind`（planned / covered / uncovered）と `length_m` を属性に持つ。QGIS・Google My Maps・BigQuery 等向け
- ナビ: 右左折の矢印・距離・案内文を画面上部に表示し、300m手前と直前に音声で読み上げ（スマホ内蔵の日本語音声、☰でオン/オフ）
- ルート逸脱時の引き直し（☰ で切替、既定はオン）: ルートから約50m以上外れた状態が続くと、離脱地点以降で最初の未走行区間へ戻る経路をオレンジの破線で案内。元ルートと走行記録は変えない。計算のため現在地を経路サーバーに送る。送りたくない場合は ☰ でオフにできる（オフでも外れたことは音声と表示で知らせる）
- シミュレーション走行（机上テスト用。GPSなしでルート上を自動走行。「ルートを外れる」で引き直しも試せる）
- 走行中は画面を消灯させない（Wake Lock、対応端末のみ）
- 通信の計測: ☰ の下部に、起動からの通信量（地図タイル枚数・経路計算回数・キャッシュ・失敗）と、直近 10 秒の応答時間・実効速度・回線の目安（良好／やや遅い／遅い／不安定）を表示。10 秒ごと更新。タイルは自前で fetch してサイズと所要時間を測る（配信元が計測ヘッダーを返さないため）。所要時間 15 ms 未満はブラウザキャッシュとみなし通信量に数えない。1 リクエストあたりの処理は配列に 1 件足すだけで、動作への影響はない

## 使い方
1. 右上「☰」→「新しいルートを作る」→ 名前を入力（または「ルートを読み込む」で GPX / GeoJSON を選択）
2. 地図をタップして経由地を順番に追加（ピンはドラッグで移動、タップで削除）→「完了」
3. 「▶ 走行開始」→ 位置情報の許可 → 運転（画面は点けたまま車載ホルダーへ）
4. 終わったら「■ 走行停止」。翌日はそのまま「走行開始」で続きから
5. 「☰」→「書き出し…」から各形式を選択。「☰」から走行記録リセット / 判定距離の調整 / 音声案内のオン・オフ

## 仕組みと前提
- 通過判定: ルートを約15mの区間に分け、GPS の軌跡が区間の中点から「判定距離」（既定25m、10〜60mで調整可）以内を通ったら「通った」とみなす。GPS精度が80mより悪い位置は判定に使わない
- 同じ道を 2 回通るルート（往復・周回）への対応（2026-11-02）
  - 向き: 走行方向（GPS の進行方位。無いときは直近 15m の移動から推定）と区間の向きの差が 60° 以内の区間だけを通過済みにする。停止中（3m 未満の移動）は向きを更新しない
  - 進捗: ルート上の現在位置（ナビと同じ位置決め）の 100m 後ろ〜150m 先の区間だけを対象にする。同じ向きで 2 回通る区間の 2 回目を残すため。ルートから外れているときは向きだけで判定
  - 位置決め: 近い候補が複数あるときは「前回位置から前に進む候補」を常に優先し、折り返し直後に逆走と誤判定しても次の fix で戻る。走行開始時は「まだ通過していない区間のうち一番手前」を選ぶ（翌日の途中再開で 1 回目側に吸い付かない）
  - 表示: ルート線と通過済みの線を進行方向の左 6m にずらして描く（判定は元の座標）。往復は 2 本に分かれて見える。同じ向きの 2 回通過は重なったまま
  - 定数は index.html 冒頭の `COV`（offsetM / dirTolDeg / back / ahead / moveMin / dirBase / trailN）で調整できる
  - 以前の版で緑になった記録は自動では戻らないので、該当ルートは「走行記録をリセット」してから走り直す
- 地図タイル: OpenStreetMap、経路計算: OSRM 公開デモサーバー（無料・利用保証なし。本格運用時は自前 OSRM か有料APIに切替）
- 案内は OSRM の右左折情報を日本語化したもの。渋滞・車線案内はなく、道路名は OpenStreetMap に名前がある道だけ読み上げる
- ブラウザのGPSは画面点灯中のみ取得。画面オフ・他アプリ表示中の裏録りが必要になったらネイティブ化（Capacitor等）する
- iPhone で「ホーム画面に追加」すると全画面で使える

## 開発・動作確認
```bash
/usr/bin/python3 -m http.server 8766 --directory ~/dev/route-drive
```
`http://localhost:8766/index.html` を開き、☰ → シミュレーション走行。
スマホで GPS を使うには HTTPS の URL が必要（GitHub Pages など）。

## 公開（GitHub Pages）

- 公開URL: https://tmurakoshi.github.io/route-drive/
- 更新: `./deploy.sh "変更内容"` を実行するだけ（push → 1分ほどで反映）。利用者は再読み込みで新しい build 番号（☰ の一番下）になる
- URL を知っていれば誰でも開けるが、アプリにデータは入っていない（ルート・走行記録は各自のスマホ内だけ）

## 他の人にルートを渡す
- ルートを作った人が ☰ →「書き出し…」→「ルートファイル（配布用）」でファイルを作り、ファイル共有の手段で渡す
- 受け取った人は ☰ →「ルートを読み込む」でそのファイルを選ぶ（経路計算なしでそのまま入る）
- 走った途中で端末を替えるときは「ルートファイル＋走行状況」で書き出すと、次の端末で続きから走れる
- 「ホーム画面に追加」で全画面。「▶ 走行開始」で位置情報を許可。走行データは各自のスマホ内にだけ保存される
